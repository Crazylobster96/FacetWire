## 2. Linux 复现命令

在仓库根目录执行 Native Bridge 验证：

```bash
cmake -S spikes/playground_ui/native \
  -B build/playground-ui-native-linux \
  -G Ninja \
  -DCMAKE_BUILD_TYPE=Release && \
cmake --build build/playground-ui-native-linux && \
ctest --test-dir build/playground-ui-native-linux --output-on-failure
```

执行 Flutter 验证和 Release 构建：

```bash
cd spikes/playground_ui

export NO_PROXY="${NO_PROXY:+$NO_PROXY,}localhost,127.0.0.1,::1"
export no_proxy="${no_proxy:+$no_proxy,}localhost,127.0.0.1,::1"

flutter pub get && \
flutter analyze && \
flutter test && \
flutter build linux --release

test -x build/linux/x64/release/bundle/facetwire_playground_ui_spike
```

运行桌面应用：

```bash
./build/linux/x64/release/bundle/facetwire_playground_ui_spike
```

## 3. 已解决问题

### 3.1 Release Native Bridge 测试编译失败

Release 配置会定义 `NDEBUG`。原测试使用标准 `assert()`，导致所有断言被编译器移除，
继而使仅由断言引用的辅助函数触发 `-Werror=unused-function`。提交 `75eede8` 保证该契约
测试即使在 Release 配置中也保留断言，避免编译失败和测试假通过。

### 3.2 Flutter Test WebSocket 返回 HTTP 503

Flutter 测试进程需要通过环回地址连接本地监听器。Ubuntu 环境中的 HTTP 代理截获了
`127.0.0.1` WebSocket 升级请求并返回 503。将 `localhost`、`127.0.0.1` 和 `::1`
同时加入大小写两套 `NO_PROXY` 环境变量后，3 项测试全部通过。

如宿主代理仍忽略 `NO_PROXY`，可仅对测试进程移除代理变量：

```bash
env \
  -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY \
  -u http_proxy -u https_proxy -u all_proxy \
  flutter test
```

依赖存在较新但不满足当前约束的版本仅为提示；本次验证不执行 `flutter upgrade`，
继续使用仓库锁定的工具链和依赖约束。
