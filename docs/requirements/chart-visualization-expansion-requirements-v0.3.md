# FacetWire Chart Visualization Expansion 0.3 需求规格

## 1. 目标与边界

本版本在不破坏 `chart.v1`、`chart.elements.v1` 的前提下，增加主题、自动布局、标签治理、
六种普通扩展图表和三种层级图表。地图、火焰图、数据写回和编辑事务不在本版本范围。

| ID | 需求 |
| --- | --- |
| CVE-SCP-001 | 原有 17 种 Chart Kind 的请求与默认渲染必须保持兼容。 |
| CVE-SCP-002 | 主题能力必须通过伴随接口加入，不能要求旧宿主修改请求结构。 |
| CVE-SCP-003 | Treemap、Sunburst、Packed Bubble 必须使用独立层级数据模型。 |
| CVE-SCP-004 | 插件不得访问文件、网络、平台 UI 或修改源数据。 |

### 本章检查

- 普通表格型数据和层级数据不会被强行合并为一种语义。
- 本轮范围能被跨平台 C ABI 和无状态渲染器完整承载。

## 2. 主题与自动布局

必须提供 Auto、Light、Dark、Business、Academic、High Contrast 六种主题。主题包括调色板、
前景色、网格色、线宽、点大小、填充透明度和文字层级。自动布局必须根据目标尺寸、系列数、
类别数和媒介决定标签密度及图例位置，不绘制隐式背景。

主题覆盖优先级为：默认值 < 主题 < Chart Style < Element Override < 交互状态。宿主可选择
主题调色板是否覆盖系列颜色。

### 本章检查

- 主题只改变展示，不改变数据值、稳定 ID 和命中语义。
- 所有主题都允许底层透明透出。

## 3. 标签系统

标签策略支持 Auto、All、Important、None。必须支持标题、类别、图例和值标签的独立字号，
类别抽样、最大标签预算、基础矩形碰撞检测和确定性保留顺序。隐藏标签不应删除对应元素身份。

### 本章检查

- 小屏幕不会因标签数量增多而无限拥挤。
- 相同输入与目标配置产生相同标签选择结果。

## 4. 普通扩展图表

| Kind | 输入语义 | 验收行为 |
| --- | --- | --- |
| Diverging Bar | 有符号系列值 | 以零线为中心水平向两侧展开 |
| Facet Line | 每系列一面板 | 共享类别轴、独立面板，避免折线交叉干扰 |
| Range Area | `minimum`/`maximum` | 绘制上下界之间的连续带 |
| Density Heatmap | `x`、`value=y`、`size=weight` | 固定网格核密度估计并输出连续颜色强度 |
| Word Cloud | category label + frequency | 确定性布局、字号映射、碰撞避免 |
| Rose | 非负类别值 | 等角扇区，半径表达数值 |

### 本章检查

- 每种 Kind 的编码通道和现有字段具有明确含义。
- Range Area、Density 和 Rose 的非法值会在绘制前拒绝。

## 5. 层级图表 Profile

层级模型由稳定节点 ID、父索引、标签、值、颜色和显隐组成。父节点必须先于子节点，必须只有
一个根节点，不允许环。Treemap 使用面积、Sunburst 使用角度和环层、Packed Bubble 使用圆面积
表达权重。每个可见节点必须携带 node ID 进入绘制命令。

### 本章检查

- 三种图表共享数据验证、颜色和语义，但布局算法相互隔离。
- 节点身份不依赖屏幕坐标或数组重新布局后的几何。

## 6. 预算、安全与跨平台

普通 Chart 继续使用类别、系列、点和命令预算。层级图表默认最多 2048 节点、64 层和
65536 命令。所有字符串、数值、父索引、深度、结构大小和 Sink 函数必须验证。实现不得保留
调用方指针；Windows/Linux 动态加载和 Apple/Android 静态注册使用同一 C 源码。

### 本章检查

- 无递归失控、无越界父索引、无不受限临时分配。
- 所有失败都可映射到稳定状态码和诊断键。

## 7. 验收标准

1. 原有17类合同测试继续通过。
2. 六种新增普通图表均产生可识别几何和值标签。
3. 六种主题与四种标签策略有单元测试和 Playground 入口。
4. 三种层级图表完成 validate、measure、render、semantics 和 hit-test。
5. CTest、Flutter Test、MSVC ASan 和 Windows Release 通过。
6. 用户手册说明数据编码、主题选择、限制和跨平台验证步骤。

### 本章检查

- 每一项功能都有自动化证据或明确人工视觉验收步骤。
- 验收没有依赖未来的 FacetWire-Forge 文件修改能力。
